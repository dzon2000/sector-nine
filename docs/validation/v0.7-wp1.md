## Start and return

1. Open **Chapter Playtest** from the opening screen or the Operations Console. Select Chapter II, III, or IV. For Chapter IV, select Independent or Corporate.
2. Select **Start Chapter Playtest**. If the browser already has a chapter run, choose **Replace Chapter Playtest** to open a new one or **Resume Chapter Playtest** to keep playing it. A failed checkpoint load leaves the previous run available.
3. Inspect the paused factory, use the normal chapter-start action, then select **Run** to advance the simulation. The Inspector's **Local playtest** controls can opt in to recording and export JSON.
4. Reload to continue the playtest. **Reset Chapter Playtest** and **Restore checkpoint** return to that run's initial handoff and clear its active recording. **Return to Campaign** saves and pauses the playtest before loading the campaign. The playtest remains available to resume.

A running campaign is paused and saved at its exact current tick when switching. If the campaign still shows its fresh introduction or has a rejected save, the switch leaves that campaign slot alone. Checkpoint validation precedes the campaign flush, and replacement commits only after that flush succeeds. If the chapter write fails afterward, the campaign remains paused with its latest progress saved. A chapter playtest shares no campaign save or recorder key. Confirmation applies to the single saved chapter playtest in this browser.

Checkpoints come from the same paid 300 Cr campaign used by the recovery tests and v0.6 launcher. The game fetches only the selected versioned build asset on first launch or confirmed reset. CI runs the paid replay and compares each entire fixture to its validated endpoint. To refresh assets after an approved replay change, run:

```sh
SEKTOR9_REFRESH_CHAPTER_PLAYTEST=1 npm test -- tests/integration/economy/v0.4-recovery.test.ts -t 'WP1 bundled chapter checkpoints'
```

The chapter slot commits source checkpoint identity, current schema game snapshot, and restart epoch atomically. Reload restores the persisted playtest; a direct playtest URL with no saved run offers recovery without seeding storage. The epoch rejects stale autosave after replacement, and the recorder key follows that epoch. Exports keep the existing format and add the starting checkpoint ID and tick, chapter, mission and chosen recipient. The original schema, rule and build provenance remains available. Recorder elapsed time begins when recording is enabled. Reading is an additional manual activity while the clock runs.
