# Human Playtest Evidence

Use when planning or evaluating actual PO acceptance and recorder exports.

1. State version, deployed/local build provenance, rule/schema, browser viewport, starting save and playtest objective. Check that any available buildCommit identifies the compiled revision; local unknown remains null.
2. Provide human checklist for setup, paid campaign, deliberate recoverable error, story clarity, mission readability, accessible controls, restore/migration and post-campaign sandbox.
3. Use recorder export only when provided by the player. Identify commands, mission transitions, observed ticks and explicitly player-declared planning, credit-waiting, mission-waiting, paused and unclassified wall time.
4. Never infer idle intent from inactivity; never retroactively reinterpret historic unclassified buckets. Keep wall-time categories separate from simulation ticks and machine diagnostics.
5. Report observed bottlenecks, production vs stockpile, credit softlocks, fatigue/repetitive clicks, strategy options and accessibility issues, citing actual evidence.
6. Contrast planned acceptance thresholds with genuine player observations. Mark absent exports, archived saves, deployed network smoke and subjective judgement as PENDING, not PASS.

PO alone signs human criteria. Output playtest summary, evidence links, outstanding manual checks and explicit acceptance request.
