# PR #2 — Independent Review Remediation

**Source review:** [PR #2, review 5819660486](https://github.com/dzon2000/sector-nine/pull/2#pullrequestreview-5819660486).  
**Scope:** P1 material ledger continuity, P2 typed recipes, save corruption checks and distinguishable cargo.

## Fixes

### P1 — Existing stock on migrated v1 factories

A migration no longer creates an empty production ledger for a populated factory. The new `opening` field records physical on-hand quantities per item (outputs, belts, typed input buffers, reserved cycle inputs) when the ledger begins. These items are *not* counted as newly produced.

Conservation: `opening + produced - consumed - sold - demolished = onHand`.

The same field is safely inferred for older v2 development snapshots without an explicit opening field, based on their existing ledger movements and current physical stock. Negative or otherwise malformed ledger entries are rejected; the IndexedDB snapshot is preserved and no reset is triggered. Migration starts no historical operational accounting for legacy games.

**Evidence:** `tests/integration/review-regressions.test.ts` migrates a populated, in-progress v1 factory and verifies conservation at migration, after a terminal sale, after 600 ticks of simulation and after demolition.

### P2 — One authoritative inventory per processor

Iron Furnace, Mechanical Assembler and Advanced Furnace all use the same recipe lookup, typed `inputBuffers` and `reservedInputs` for input acceptance, recipe-start reservation and output completion. `oreInput` survives only as a **legacy compatibility mirror** for old v0.1 fixtures and exported state; the engine updates it from typed inventory. It is not used to decide production, capacity, sale or demolition.

Save validation rejects v2 furnace snapshots where this legacy mirror differs from the typed buffer, rather than silently trusting either contradictory quantity. v1 migration initializes the typed stock from the original legacy field.

**Evidence:** review regression test verifies mismatch rejection, synchronization after processing and conservation. Existing v0.1 throughput/economy reference tests continue to run.

### P2 — Strict v2 snapshot schema validation

Technology keys must be the exact three recognized IDs with boolean values. Coal deposits must match the two fixed coordinates and expected array structure. Material inventories may only contain items accepted by their machine's recipe, with integer quantities 0–4; unknown items, unexpected fields, invalid ledger keys and negative balances are rejected without overwriting stored saves.

**Evidence:** invalid combinations are asserted in `tests/integration/review-regressions.test.ts`.

### P2 — Visually distinct physical cargo

The renderer displays distinct readable two-letter cargo badges for all five types (Or, In, Co, Ge, St), with item-specific color as secondary support. Processors show typed buffer counts *including missing inputs*, plus visibly marked reserved materials while active.

**Evidence:** `tests/unit/cargo.test.ts` checks distinct glyphs, missing inputs, reserved stock and the per-recipe labeling. Browser tests continue to exercise the Pixi board.
