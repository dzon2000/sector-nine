## 1. Delivery contract

Implement the approved *First Signal* design: direct mouse/trackpad rotation; desktop-centered map and persistent mission HUD; reproducible, opt-in playtest logging; copper and silicon resource chains; minimal, site-wide coal-fueled power for **circuit fabricators only**; new Chapter II missions M8–M10; and continuation of the Prometheus story.

### Non-negotiable invariants

- Follow `AGENTS.md`. All repo documentation, code comments, identifiers, commit messages and PR descriptions are **English**.
- Keep TypeScript simulation deterministic and fixed-step; never couple simulation to rendering, pointer events, browser time, or persistence. Integer cents only. Physical, directional transport, backpressure and terminal sales remain authoritative.
- Preserve every existing reference result: **58.50 Cr/60 ticks iron-ingot line**, **38.00 coal**, **92.25 gears**, **116.625 steel**. Do not change pre-v0.4 recipes, sale prices, costs, technology fees, resource deposits, 12×12 board, terminal coordinates or refunds.
- New economic parameters, deposit coordinates and M8–M10 thresholds are **provisional hypotheses**. Test them against the actual TypeScript engine and obtain explicit product-owner approval before declaring them frozen. Record approved choices in a v0.4 ADR. No silent retuning to make tests green.
- Respect all v0.1/v0.2/v0.3 saves and mission rules. Existing v0.3 `DONE` does not automatically advance. An explicit **Begin Chapter II** action preserves factory, cash, achievements and prior diagnostics. Legacy M6/M7 rules remain active until their completion.
- The game is entirely local. No telemetry or backend, no offline production, no imposed wait timers, no randomness, no fabricator-wide power requirement for old machines.
- Do not introduce out-of-scope storage, splitters, power cables/network topology, circuits with wire/wafer intermediate recipes, map expansion, contracts, or story branching.
- Do not merge the PR, close issues or publish a release without explicit product-owner approval. Do not automatically start later WPs; show results at each gate.

### Recommended execution order

**WP0 → WP1 → WP3 → WP2 → WP4 → WP5 → WP6.** WP identifiers are retained from the approved design, but *physical feasibility (WP3) runs before finalizing mission/progression (WP2)*. This avoids hard-coding unverified thresholds. WP1 may use temporary **new-system-only** parameters for headless probes; they are not approved balance values until WP3 sign-off. If one implementation requires an earlier part of a later WP, make the dependency explicit and keep the scope small.

### Required progress report at every gate

Provide: (1) files/commits changed, (2) red tests written first, (3) tests passing with exact commands and counts, (4) acceptance criteria satisfied, (5) deviations and unresolved risks, (6) explicit approval request for the next WP. Push coherent commits to the feature branch; avoid force-pushing. Report actual GitHub Actions status rather than assuming CI passed.

## 10. Technical review hazards — mandatory callouts

1. **Map saturation:** V0.3 owner playtest used all 3 iron and both coal deposits. New deposits cannot assume empty tile routes. Prove conversion and cash recovery from realistic saved factories; occupied new deposit tiles must not overwrite structures.
2. **Fuel material ledger:** Burning coal is a consumption event distinct from sale and demolition. Ensure conservation statements and save migrations do not falsely count it as disappearing material.
3. **Zero-demand power exploit:** An idle factory cannot accumulate 57/60 “powered ticks” for an M10 win. Document exact denominator and qualification test.
4. **One terminal and congestion:** Circuits and steel share terminal physical intake; published rates must be demonstrated with simultaneous actual sales.
5. **Mission-rule coexistence:** Do not globally replace v2/v3 rules with v4. Continue legacy players to foundry DONE first; Chapter II starts by explicit action and new rule context.
6. **Source SHA:** A PR HEAD may differ from merge commit or release artifact SHA. Export the commit used to compile this frontend, not whichever Git ref is latest when JSON is exported.
7. **Large viewport bug:** The issue reproduces at 1920×1080 as well as smaller desktop sizes. No tests limited solely to compact viewports.
8. **Manual evidence:** Do not claim genuine migrated saves, accessibility, or user comprehension have been tested if evidence is only synthetic/headless.
