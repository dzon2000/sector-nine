## RED → GREEN → REFACTOR

- New schema test on the baseline: **6 failed, 1 passed**. New game used schema 3, schemas 1–3 loaded, schema 4 followed old validation, and missing diagnostics were synthesized. Future-schema rejection already passed.
- The queued-save protection regression on the baseline failed because the normal write resolved over a rejected slot. With WP1 the rejected snapshot is preserved. The queue double also verifies in-flight transaction completion, invalidation of pending stale writes, suppression of stale requests during restart, denial of stale writers in other tabs, and valid post-restart writes.
- QA follow-up RED: an older tab could overwrite the new campaign, recipe cycles accepted missing reservations, and a zero-cycle mine could become permanently invalid. GREEN: **9/9** schema/recovery and **3/3** queue tests. Refactored fixture initialization and ran the full test and build commands listed above.
