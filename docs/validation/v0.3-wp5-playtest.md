## Tutorial and narrative

The v0.3 M6 contextual objective now explains:
- Unlock Mechanical Components (120 Cr).
- Feed the assembler with two iron ingots per gear.
- Sell **at least nine gears in every rolling 60 active ticks for 120 consecutive qualifying ticks**.
- Use the inspector to identify missing ingots and blocked outputs; expand upstream capacity instead of waiting indefinitely.

M7 explains:
- Unlock Advanced Smelting (180 Cr).
- Maintain **at least seven gears, seven steel and 175.00 Cr operating profit simultaneously in each rolling 60 active ticks**, for a consecutive 120-tick streak.
- Each steel cycle uses two iron ingots and one coal.
- Retain profitable production while rerouting material; inspect bottlenecks and the live objective comparison.

Existing Chapter I M1–M4 tutorials, M5 coal milestone, foundry skip/replay and Prometheus archive context remain in place. v0.2 saves already in M6/M7 receive **legacy guidance** matching their original cumulative eight-gear/eight-steel completion rules, not the new mission instructions. The Foundry Directive remains skippable and replayable; its last page has v0.3 optimization context with legacy fallback.

## Optional local recorder — player workflow

1. Open **Inspector → Local playtest**. Recording is initially **off**.
2. Select **Start recording**. It starts at the current game tick, regardless of prior campaign progress.
3. While playing, explicitly choose **Planning / routing**, **Waiting for credits**, or **Unclassified**. These labels are *user observations*, never inferred from mouse inactivity or simulation ticks.
4. Continue building, rotating, demolishing, researching, inspecting bottlenecks, pausing and changing routes normally. Only **successful** actual commands are counted.
5. Select **Stop recording**, then **Export local JSON report**. The download is named `sector-nine-playtest.json`. No remote upload is performed.
6. Optionally discard the local recording. A new factory reset also clears the local recorder. Starting a new recording replaces the previous local recording; export first if needed.

Data is held in the browser's local storage under `sector-nine-v0.3-local-playtest`, separate from the IndexedDB game save. An active recording resumes after reload. Time between sessions is excluded by resetting the browser observation timestamp on reload; simulation offline time is never manufactured. Malformed or inaccessible optional recorder storage is ignored without blocking the actual game save.

## Exported evidence format

`format: "sector-nine-playtest-v1"` records:
- **schemaVersion**, **missionRuleVersion** — captured from the actual game save when recording starts. Newly exported reports distinguish new-rule v3 campaigns from migrated legacy v2-rule campaigns; older local recordings that predate the fields remain compatible and may omit them. This is optional provenance, not independent proof of individual mission windows. A build/commit identifier is not included because the current build has no reliably injected identifier.
- **activeTicks** — actual positive simulation-tick deltas observed while the recorder was enabled.
- **wallMs** — elapsed time while the browser session's recorder was active (excludes reload downtime).
- **pausedMs** — time when simulation was paused or introduction open.
- **planningMs**, **waitingMs**, **unclassifiedMs** — explicitly annotated *unpaused* wall-clock time. A player's explanation of planning/waiting can be recorded independently of idle mouse behavior.
- **commands** — counts of successful `place`, `turn`, `demolish`, `research` actions, plus **commandEvents** including simulation tick and relative elapsed milliseconds. No failed attempts are counted.
- **usedDeposits** — iron/coal deposit grid coordinates used by existing mines at recording start or successful mine placements during the session.
- **missionTransitions** — transitions witnessed by the recorder with active-tick number.
- **inputStarvedEntityTicks**, **outputBlockedEntityTicks** — sums of engine-generated diagnostic entity states seen while the recorder was active.

The export contains **no identifying name, email, user agent, IP address, device ID or external telemetry endpoint**. Recorded schema/rule versions are non-personal gameplay metadata. The reviewed pre-change owner export does not contain them, so it cannot independently establish which M6/M7 rule version was played. It is intended for optional, local manual sharing with the reviewer.

**Interpretation:** Active ticks and wall-clock time are deliberately different. Planning and waiting buckets represent human annotation, **not automated evidence of intent**. A report can demonstrate decisions and timing, but does not by itself prove player comprehension. Human playability remains a WP6 acceptance gate.

## Limitations

Local storage is browser/profile-specific. It is not a server-backed analytics archive; clearing browser storage removes the in-progress recording unless exported. Paused time overrides planning/waiting for time-bucket accounting, avoiding double counting. The classification does not infer actual user intentions.

WP5 does not add gameplay resources, offline progress, storage buildings, new chapters, telemetry backends, price retuning, or automatic mission completion. Final human playtest and release paperwork belong to WP6.
