## 2. W5.1 — Verified compiled artifact provenance

The Vite `define` embeds a **40-character lowercase Git commit** only when `GITHUB_ACTIONS=true` and `GITHUB_SHA` is valid. Untrusted, absent or malformed local SHA results in JSON `null`, never a branch label, package version or fabricated hash. The additional GitHub Actions step checks the actual checkout HEAD and that the compiled JS contains the exact expected SHA. A verified SHA identifies **the checkout used to compile the artifact**; local copies without a trusted CI build do not imply verified origin.

The build commit is supplied to the recorder when a session starts. It is not read dynamically at export time.

## 3. W5.2 — Origin is immutable across reloads/upgrades

`startPlaytest(game, now, BUILD_COMMIT)` captures `schemaVersion`, `missionRuleVersion` and `buildCommit` **at recording start**, independently of future game state. `resumePlaytest` and `advancePlaytest` preserve all three. Export retains `format: "sector-nine-playtest-v1"` and includes `buildCommit: string|null`. Legacy recordings that did not contain a commit remain readable and export `null`; missing schema/rule values remain absent as in historical v1 reports.

**Mixed-build limitation:** A recording resumed after a deployment still names its **originating build**. It does not attest that subsequent gameplay ran solely on that build. This v0.4 scope does not add per-command build-change events or automatic session splitting, and the original identity is never overwritten.

## 4. W5.3 — Explicit waiting for mission/stability

Adds player-selected `waiting_mission` without changing existing `waiting` (**waiting for credits**), `planning`, `unclassified` or automatically paused time. Exports `waitingForMissionMs` separately from existing `waitingMs`; report sum reconciles to elapsed observed `wallMs`. The player changes classification through a local radio control; the engine never infers intention from activity or credits.

Session absence/offline time is not charged during a reload; paused time remains distinct. Old sessions have `waitingForMissionMs=0` in new exports, with their existing waiting totals preserved rather than retroactively reassigned.

## 5. W5.4 — Observed power ticks, privacy

The recorder adds optional `poweredTicks` and `unpoweredTicks`, counting only **newly observed authoritative simulation power history** where demand is nonzero. A served demand tick increments `poweredTicks`; an unserved request increments `unpoweredTicks`. Duplicate observations are not counted, zero demand is excluded, and gaps larger than the bounded 60-tick history are not extrapolated. These metrics do not affect simulation outcomes.

Recording is **off by default**, local-only in browser storage and downloaded JSON. No network telemetry, user identifiers or device metadata were introduced.

## 7. W5.7 — Approved Chapter II story

Narrative is represented as contextual, replayable **optional** transmissions. No modal opens automatically during active production:

1. **Opening** — Unknown Client's Route 09 request; Corporate Operations challenges its missing signature. `Inspect Request` or return to factory; stored `storySeen` preserves dismissal across reload.
2. **After M8** — Materials Verified; erased manifest bears PROJECT PROMETHEUS signature.
3. **After M9** — Signal Recovered; client demands stable circuits and self-sufficient power.
4. **After M10** — Prometheus partial archive identifies **SECTOR 9 — SUBLEVEL 03**, followed by Corporate priority override. Choice to obey or defy is a **future release tease**, not a gameplay branch.

Each unlocked transmission is read/skipped/replayed via accessible controls. The latest dispatch is visible as a non-modal HUD note. On Chapter II `DONE`, `First Signal Restored` replaces the Chapter I-only title; factory, money, structures and simulation remain available for free play.

## 9. Remaining risks for WP6

- Real human v0.3 saves and a human full-chapter playtest are not available as automated proofs; acceptance remains WP6.
- Waiting classification is **player-declared**, not a reliable causal inference. Reports distinguish waiting for credit from waiting for mission but do not automatically decide which classification is correct.
- A recording spanning multiple artifact builds preserves only **origin SHA**, not every intermediate build (documented limitation).
- Optional power metrics are bounded by available diagnostic history, so missed power events beyond that history are not reconstructed.
- UI screens are accessible via named buttons/keyboard tests, but no external assistive-technology audit was conducted.
- WP6 should verify M8/M9 feedback visibility, Sublevel 03 narrative pacing, source deposit clarity and credit-vs-mission waiting time with actual player behavior.
